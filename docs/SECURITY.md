# Security design

## Authentication and sessions

Passwords use Argon2id through `argon2-cffi`. Opaque cryptographically random access/refresh tokens are stored as SHA-256 hashes, never plaintext. The access token lives only in React memory and expires in 15 minutes. A SameSite=Strict HttpOnly refresh cookie rotates on use, with an eight-hour absolute session lifetime. Cookie `Secure` is enabled in production. Consumed refresh hashes identify replay and revoke the session. Logout and administrator role/deactivation changes revoke server sessions immediately. Browser refresh requires both an allowlisted Origin and the custom client header; CORS grants only configured origins.

The demo password is generated by `scripts/configure.py`/`seed.py`, stored only in ignored local files, and never printed by startup scripts. Local demo credentials are not suitable for shared deployment. Five failed logins introduce temporary progressive account lockout; endpoint/IP throttles bound request rates. Unknown users receive the same login error and perform a dummy Argon2 verification.

## Authorization

`security.py` defines an explicit permission matrix and case-level scoping. Analysts access owned/assigned cases; compliance reviewers access assigned cases. Managers, checkers and auditors have broader domain access according to their responsibilities. Every case-derived file, report and simulation rechecks the object scope. Administrators manage configuration and identities, without `LC_VIEW` or `CASE_APPROVE`. The UI reflects permissions for usability; the server remains authoritative.

## Documentary controls

Limits: 6 MB entire HTTP body, 5 MB document; streamed requests are counted before multipart parsing. The extension and byte signature must agree. Executables, paths, active PDF markers and EICAR test content are rejected. Browser-provided MIME is ignored. The scanner is a demonstration abstraction, not antivirus. Bytes are stored transactionally under a database UUID. Downloads are authorized, attachments use server-generated filenames, and document responses receive a sandbox CSP. SHA-256 duplicates and unique document versions prevent silent replacement.

## Business controls

Schemas reject unexpected fields, invalid dates, negative/huge/nonfinite numbers and unsupported currencies. Exact decimal arithmetic avoids binary floating-point tolerance errors. The state machine rejects impossible actions. Final approval requires current inputs/configuration/date, no unresolved current findings, complete checklist and a distinct checker. Critical findings, required evidence and expiry controls cannot be waived. Business data updates produce versions, and stale requests receive 409. PostgreSQL locks and SQLAlchemy version counters protect concurrent transitions.

## Audit, observability and exports

No ordinary API can modify or delete audit events. Every event includes actor, role, action, entity, timestamp, details, correlation ID and hash-chain links. The singleton chain head detects missing tail events and serializes writes. Privileged database administrators are outside this mechanism's trust boundary: WORM/SIEM anchoring remains required for regulated usage.

CSV export neutralizes formula prefixes; exports are scoped and audited. JSON/PDF reports have synthetic labels. Parameterized ORM queries avoid user-concatenated SQL. React escapes displayed text; report markup is escaped. Responses suppress internal exception messages/paths/SQL parameters. Logs omit tokens/passwords and record only safe request metadata. Use `--no-access-log` to avoid logging arbitrary query strings.

CSP, frame denial, MIME sniffing prevention, no-referrer, permissions restrictions and no-store API responses are set. HSTS is production-only; TLS must terminate at the deployment gateway. Swagger's documentation page has a distinct CSP to load its upstream UI assets.

## Password recovery / MFA architecture (not active features)

Local demo administrators can reset a synthetic account's password using the governed user endpoint/UI. It enforces password policy, clears lockout, revokes all sessions and logs the actor/reason without the password. This administrative demo endpoint is disabled in production.

Production self-service recovery must accept a generic response regardless of account existence, issue a random single-use token, persist only its hash/expiry/purpose/user ID, dispatch only through a verified delivery adapter, consume it transactionally, apply password policy and revoke every session. Rate-limit by account and network; never reveal reset tokens in normal API responses. A self-service reset service is intentionally not exposed until that delivery/identity boundary exists.

MFA requires protected enrollment, verified second-factor challenge, encrypted TOTP seed under managed keys, hashed recovery codes, replay/time-window checks and step-up on approvals/role changes. It is documented future architecture, not a claim of working MFA. Prefer enterprise OIDC with managed MFA before production.

## Deployment and incidents

Use TLS, a least-privilege runtime database principal separate from the migration owner, private network storage, encrypted database/backups and managed keys. Docker's demo database user owns its schema for convenience; it must not be reused as a production privilege model. Export/incident access belongs to accountable roles. The worker derives operational risk signals from repeated login failures/replay events and administrators record investigation decisions. This is not a SIEM.

Incident response concept: disable affected users/sessions, preserve audit and database snapshots, investigate using correlation IDs, rotate compromised infrastructure credentials, restore from verified backups if required, and record remediation through change control. Do not erase audit records to “clean up” an incident.

Dependency scans and heuristic secret scans are repeatable. Current findings and narrowly scoped development-tool exceptions are in SECURITY_RESULTS.md. External penetration testing and formal accessibility/security assessment remain outstanding.
